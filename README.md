🔐 RSA Encryption / Decryption App

An interactive web app built with Streamlit that demonstrates how the RSA public-key cryptosystem works. Choose two prime numbers, generate a key pair, then encrypt and decrypt text messages, all from your browser.

⚠️ Educational purposes only. This project is a learning tool and is not secure for real-world use. See Limitations.

✨ Features
Key generation from two user-supplied primes (p and q)
Input validation with clear error messages (non-prime values, p == q, p × q too small)
Recommended primes list to get started quickly
Text encryption that outputs a compact Base64 string
Text decryption with the cipher auto-filled from the encryption step
Session state keeps your keys and ciphertext between interactions
Reset button to clear everything and start over
Built-in "What is RSA?" explainer
🧠 How It Works
Pick primes p and q.
Compute the modulus n = p × q and Euler's totient φ(n) = (p − 1)(q − 1).
Choose the smallest public exponent e ≥ 3 such that gcd(e, φ(n)) = 1.
Compute the private exponent d such that (e × d) mod φ(n) = 1.
Encrypt each character: c = m^e mod n, where m is the character's Unicode code point.
Decrypt each value: m = c^d mod n.

The encrypted numbers are packed as 4-byte unsigned integers (struct) and Base64-encoded so the ciphertext is a single, easy-to-copy string.

Key	Components
Public key	(e, n)
Private key	(d, n)

📖 Usage
Generate keys: enter two different primes (try the recommended ones, e.g. 61 and 53) and click Generate Keys.
Encrypt: type a message and click Encrypt. A Base64 ciphertext appears.
Decrypt: the ciphertext is auto-filled; click Decrypt to recover the original message. You can also paste a ciphertext generated with the same keys.
Reset: click 🔄 Reset to clear the keys and ciphertext.

📋 Input Rules
Rule	Reason
p and q must both be prime	Required for RSA to work
p ≠ q	Equal primes produce a weak, invalid modulus
p × q > 127	The modulus must exceed the largest ASCII code
Prefer n ≥ 256	Smaller values may fail to encrypt some characters correctly (the app shows a warning)

Characters with Unicode code points larger than n cannot be encrypted correctly, so use larger primes if your message contains non-ASCII characters.

⚠️ Limitations

This app is designed to teach RSA, not to protect data. In particular:

Tiny keys: real RSA uses primes hundreds of digits long; small primes can be broken instantly.
Character-by-character encryption: each character is encrypted independently with no padding, which makes the ciphertext vulnerable to frequency analysis.
No padding scheme (such as OAEP) is used.
Brute-force modular inverse is used instead of the Extended Euclidean Algorithm, so key generation is slow for very large primes.
Deterministic public exponent: e is always the smallest valid value rather than a standard choice like 65537.

For production-grade cryptography, use a vetted library such as cryptography.
